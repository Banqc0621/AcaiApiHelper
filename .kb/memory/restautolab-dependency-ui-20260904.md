# RestAutoLab 依赖设置与调试界面整改记录

- 记录时间：2026-09-04
- 项目：RestAutoLab
- 关联范围：收藏夹依赖设置、接口顺序、历史记录菜单、接口扫描

## 最终需求（以最近一次确认 为准）

1. 收藏夹依赖设置中的“收藏夹接口顺序”显示序号、HTTP 方法和完整 URL 路径。
2. 上游接口、下游接口的表格单元格和下拉选项同样显示完整方法 + URL，不能只显示接口名。
3. 响应字段与目标参数支持候选下拉，同时允许用户手动输入；字段过长时可换行并通过悬浮提示查看完整内容。
4. 依赖设置主按钮文案为“保存”；点击保存后再次打开同一收藏夹，必须回显之前保存的依赖边和多条字段映射。
5. 取消按钮使用中文“取消”，依赖表格不显示“检测方式”列。
6. 历史记录右键菜单按内容自适应宽度，不得被固定宽度或分隔线撑成长条。
7. 接口扫描只允许项目生产源码，排除 Maven/Gradle 依赖、测试源码和编译输出中的 Controller。

## 已遇到的异常与根因

- 顺序列表曾使用 Swing HTML inline span。部分 IntelliJ LaF 对 span 宽度计算不一致，实际界面只剩“1.”、“2.”、“3.”，方法和 URL 被渲染层吞掉。现改为纯文本行渲染，保证内容和首选宽度稳定。
- 接口名称历史数据可能已经是“[GET] /admin/path - methodName”完整展示串。短名称清洗逻辑已覆盖该格式，但最终需求改为上下游也显示完整路径，因此依赖表和下拉框现在统一走 `fullApiLabel`。
- 历史菜单曾以 116px 作为最小宽度，且分隔线也固定为 116px，导致“发送/删除”菜单视觉过长。现改为内容自适应、最小 88px。
- 依赖配置保存依赖收藏夹稳定 `folderId`。旧数据缺少或重复 id 时会先补齐 UUID；空依赖列表也保留配置键，避免下次误判为首次打开并重新生成顺序边。

## 收藏夹批量测试整改（2026-09-07）

### 根因

- 收藏夹普通“批量测试”和多选“批量测试”原先直接逐个调用 HTTP 服务，绕过了依赖设置，
  因此不会按拓扑顺序等待，也不会把上游响应字段注入下游参数。
- 收藏夹“依赖链批量测试”每次都重新运行自动检测，可能覆盖用户在依赖设置中保存的关系和字段映射。
- HTTP 异常/取消分支使用接口模板路径写历史，路径参数和查询参数在失败请求中丢失；历史面板默认只显示当前接口，
  批量执行后容易误以为只产生一条历史。

### 已落地

- 收藏夹文件夹批量测试统一通过 `ChainTestExecutor` 执行：当前文件夹及子文件夹按收藏顺序收集，
  有保存依赖时使用保存的拓扑边和多字段映射；未配置依赖时保持收藏顺序串行执行。
- 每个请求完成回调都会更新对应收藏接口状态和处理进度（`n/total · 状态 · 接口`）；执行完成后历史 Tab 自动切换为“全部接口”范围，
  可看到每个实际请求生成的独立记录。
- 多选收藏接口在同一文件夹时复用该文件夹保存的依赖；跨文件夹多选保持选择顺序执行，避免混用不同文件夹依赖配置。
- 依赖链收藏入口优先读取已保存依赖，只有首次未保存时才自动检测。
- `HttpExecutorService` 在 URL 构建完成后保存最终 URL，网络异常和取消结果同样写入完整基础地址、路径参数和查询参数；取消请求也触发历史监听器。

### 验收规则补充

- 点击收藏夹“批量测试”后，状态栏从 `0/total` 更新至 `total/total`，每个实际发出的请求都应在历史中有一条记录。
- 有依赖边时，下游只能在上游通过后发送；上游失败时下游显示跳过且不发送请求；字段映射按保存配置注入。
- 历史记录 URL 必须是最终 URL（例如 `http://host/users/42?verbose=true`），不得退化为 `/users/{id}` 模板。

## 验收规则

- 顺序列表示例：`1. GET /admin/box/blindBoxList`。
- 上游/下游下拉示例：`GET /admin/box/blindBoxList`，不得退化成 `blindBoxList`。
- 保存一条边及多条字段映射后重新打开，producer、consumer、sourcePath、targetParam 均保持。
- 测试、构建和 `git diff --check` 全部通过后才可交付插件包。

## 请求按钮布局整改（2026-09-07）

### 用户反馈与根因

- 「发起请求」按钮曾先后采用 Tab 栏悬浮覆盖层、再采用独立顶部工具栏；在不同窗口宽度下与接口方法/URL 脱离，视觉上像靠左漂浮控件，且窄窗口时 URL 区域可能被 Swing `BorderLayout` 算成负宽度。

### 已落地

- URL 是可收缩的中央区域，空间不足时优先收缩到 0；按钮保持 28px 高度、可点击区域和无障碍名称/tooltip，窗口缩放或滚动条变化不会漂移到左侧或覆盖接口标签。
- 请求中仍同步 spinner、禁用状态和“点击取消”提示；请求完成恢复执行图标和“发起请求”提示。

### 回归验证

- 新增 `RequestActionRowLayoutTest`，覆盖 800/400/240px 三种宽度，断言按钮右缘稳定、URL 不出现负宽度、按钮始终在行内。

## 2026-09-07 规则语义与批量测试复核（#90/#91）

### 异常规则最终语义

- `HTTP_VALUE`：字段名留空时才校验 HTTP 状态码白名单（仅 100–599 整数）；填写字段名时校验响应 JSON 字段白名单，支持数字和字符串（例如 `code=301`、`code=SYSTEM_ERROR`）。
- `FIELD_VALUE`：校验响应 JSON 字段告警值黑名单；命中即失败，未命中或字段缺失通过（例如 `code=500/501` 失败，`code=200` 正常）。字段支持点号路径（如 `data.code`）。
- 旧配置中无字段且全为字符串的 `HTTP_VALUE`（如 `SYSTEM_ERROR`）会自动迁移为 `code` 响应字段白名单；混合状态码/字符串的歧义配置不猜测，评估器只采用合法状态码，避免再次出现“HTTP 200 不在 [SYSTEM_ERROR]”的错误。
- 首次使用预置 HTTP 状态码 `200/201/204` 白名单 + `code=500/501/9999` 告警值；另提供默认关闭的 `HTTP_VALUE code=200` 白名单模板，避免无 `code` 响应的接口被误伤。

### 批量测试与历史验收

- 收藏夹批量测试统一使用 `ChainTestExecutor`：按收藏顺序建立无依赖执行序列，有依赖时按拓扑顺序执行；上游失败会跳过下游，不发送下游请求；字段映射逐条注入下游参数。
- 每个实际发送的请求由 `HttpExecutorService` 的历史监听器记录一条；历史中的 URL 使用最终基础地址、路径参数和查询参数（如 `http://host/users/42?verbose=true`），网络异常/取消也保留已构建的最终 URL。
- 批量执行状态使用 `当前/总数 · 状态 · 接口` 文本展示；已移除左右两处独立 JProgressBar，避免蓝色填充块和额外占位，同时保留逐项进度与完成汇总。

### UI 复核结论

- 依赖设置的顺序列表、上游/下游表格和下拉选项统一显示 `HTTP 方法 + URL 全路径`；“保存”按钮写入当前收藏夹，关闭后再次打开恢复依赖边和多字段映射。
- 前置脚本页增加环境信息卡、脚本/变量分区边框，变量覆盖表启用主题感知网格线，兼容明暗主题。
- “发起请求”按钮继续固定在接口方法/URL 行最右侧，URL 区域可收缩且不产生负宽度；不使用悬浮覆盖层。
